AI 代码开发平台产品原型与交互说明

本文档描述 AI 代码开发平台 MVP 的页面结构、信息架构、核心交互、状态反馈、异常处理和页面验收要求。 它用于指导后续 UI 原型、前端页面拆分和交互评审。

1. 设计原则

任务优先

这是研发工作台，不是展示型网站。首屏应直接进入项目、代码、需求和流程状态，不设置营销式欢迎页。

状态清楚

用户必须随时知道当前项目处于哪个阶段、阻断原因是什么、下一步能做什么、谁需要审批。

证据可见

AI 的问题、方案、代码修改、CR 结论都要能看到来源，包括需求片段、代码文件、测试日志和审批记录。

人工可接管

AI 自动生成的内容不能变成黑箱。关键内容都要支持查看、评论、驳回、重跑、人工编辑和回退。

2. 信息架构

MVP 的信息架构围绕“项目”展开。进入项目后，用户在同一个工作台内完成代码浏览、需求澄清、设计审批、代码改动、自测和 CR。

  │   ├─ 方案
  │   ├─ 详细设计

3. 全局应用框架

产品采用工作台型布局。桌面端优先，移动端以查看和审批为主，不要求完整代码编辑体验。

顶部栏：产品名 / 项目切换 / 全局搜索 / 待审批 / 用户菜单
左侧栏：项目导航，代码、需求、澄清、方案、详细设计、编码、自测、CR、交付
主工作区：当前页面主体，例如代码编辑器、问题列表、方案文档、Diff
右侧上下文面板：当前阶段状态、反思报告、审批、证据链、下一步动作
底部任务条：后台任务、AI 运行状态、测试运行状态、最近错误

布局规则

  • 顶部栏固定，高度保持紧凑，承载项目级切换和全局状态。
  • 左侧栏固定宽度，支持折叠，当前阶段用状态点标识。
  • 主工作区优先保证代码、文档和 Diff 的可读宽度。
  • 右侧上下文面板可收起，避免遮挡代码编辑。
  • 底部任务条只显示运行中和失败任务，成功任务进入历史记录。

4. 导航与状态模型

阶段状态

状态 视觉表达 用户含义
已完成 绿色状态点或完成标记。 阶段通过门禁，可查看产物。
进行中 蓝色状态点，显示运行任务。 AI、测试或用户正在处理。
待审批 黄色状态点，右侧面板显示审批人。 需要人工确认才能继续。
阻断 红色状态点，展示阻断原因和恢复动作。 当前阶段不能继续自动推进。
未开始 灰色状态点。 前置阶段尚未完成。

导航行为

  • 用户可以进入任意已开始阶段查看内容，但不能跳过门禁执行后续动作。
  • 点击左侧阶段导航时，右侧上下文面板同步展示该阶段的产物、反思和审批状态。
  • 存在阻断状态时，顶部栏显示项目级提醒，点击后定位到阻断阶段。
  • 后台任务运行中时，用户可以切换页面，但对应阶段动作按钮进入加载或只读状态。

5. 页面原型说明

页面 主要区域 核心操作 关键状态
P-001 项目列表 项目表格、筛选器、创建项目入口。 创建项目、搜索项目、进入工作台、归档项目。 空项目、加载中、创建失败、无权限。
P-002 项目上传 上传方式、上传进度、解析结果、环境声明。 上传 ZIP、填写 Git 地址、确认根目录、重新解析。 上传中、解析中、解析失败、密钥扫描告警。
P-003 代码工作台 文件树、代码编辑器、Diff、搜索、右侧阶段面板。 打开文件、编辑保存、查看 Diff、人工接管。 只读、编辑中、保存失败、文件冲突。
P-004 需求分析 需求文档、AI 问题列表、影响模块、导出区。 上传需求、触发分析、筛选问题、导出问题。 无需求、分析中、问题为空、分析失败。
P-005 澄清 问题详情、业务反馈表单、AI 归纳、澄清历史。 填写答案、确认归纳、继续追问、进入方案。 待业务反馈、答案冲突、可开发、仍需澄清。
P-006 方案设计 方案正文、影响范围、风险、Agent 策略、审批。 生成方案、重新生成、评论、审批通过、驳回。 生成中、待审批、已驳回、已通过。
P-007 详细设计 设计文档、文件计划、测试矩阵、任务列表。 生成详细设计、编辑评论、审批、生成编码任务。 缺少方案、生成失败、待审批、已通过。
P-008 编码与 Diff Agent 任务、代码变更、Diff、实现说明。 触发编码、停止任务、接受变更、拒绝变更、人工编辑。 编码中、冲突、任务失败、待自测。
P-009 自测 测试命令、运行日志、测试结果、失败归因。 运行测试、终止测试、查看日志、触发修复。 运行中、通过、失败、环境异常。
P-010 CR 问题列表、文件定位、严重级别、修复建议。 触发 CR、修复问题、标记已处理、申请豁免。 无问题、高危阻断、待修复、已豁免。
P-011 交付报告 需求链路、设计链路、代码变更、测试、CR、风险。 生成报告、导出、确认交付。 未完成、可交付、存在风险。
P-012 设置 成员权限、模型配置、沙箱策略、环境声明。 添加成员、配置角色、保存环境声明、测试沙箱。 配置缺失、保存失败、权限不足。

6. 代码工作台交互

代码工作台是平台的主操作面。它需要像 IDE 一样可靠，但不要求在 MVP 中完整复制 VS Code 的所有能力。

桌面端布局

┌────────────────────────────────────────────────────────────────────┐
│ 顶部栏：项目 / 分支 / 阶段状态 / 全局搜索 / 待审批 / 用户菜单        │
├───────────────┬───────────────────────────────┬────────────────────┤
│ 文件树         │ 编辑器 / 文档 / Diff 主区域      │ 阶段上下文面板       │
│ 搜索           │                               │ 当前阶段             │
│ 打开的文件      │                               │ 反思报告             │
│ 变更文件        │                               │ 审批动作             │
│                │                               │ 证据链               │
├───────────────┴───────────────────────────────┴────────────────────┤
│ 后台任务条：AI 运行、索引、测试、CR、错误提醒                         │
└────────────────────────────────────────────────────────────────────┘

关键交互

交互 行为 限制
打开文件 点击文件树节点，在编辑器区域打开文件，多文件用标签页切换。 大文件默认只读，提示用户下载或局部查看。
编辑文件 用户点击编辑模式后可修改文件，保存后进入未提交变更。 AI 任务运行中修改同一文件时提示冲突风险。
查看 Diff 变更文件列表点击后展示左右对比或行内对比。 二进制文件只显示变更状态，不显示内容。
人工接管 用户可停止 AI 任务并接管当前分支。 接管后必须记录操作人，后续 AI 使用新快照。
定位证据 从 AI 问题、方案、CR 点击引用，跳转到需求片段或代码位置。 引用不存在时显示“证据失效”，并要求重新生成上下文包。

7. 阶段流转交互

阶段流转不能只是一个按钮。每次进入下一阶段前，页面应展示本阶段产物、反思结论、阻断问题、审批要求和下一步影响。

阶段推进面板

区域 内容 交互要求
当前状态 阶段名称、状态、执行人或 Agent、开始时间、耗时。 状态变化实时刷新。
阶段产物 问题清单、澄清记录、方案、设计、代码变更、测试报告。 产物可打开、可复制、可导出。
反思报告 评分、是否可继续、阻断问题、非阻断问题、证据链。 阻断问题置顶展示，不被折叠隐藏。
审批动作 通过、驳回、退回修改、申请豁免。 审批必须填写备注或选择原因。
下一步影响 进入下一阶段后会触发什么任务、锁定哪些版本。 用户确认前必须可见。

常见动作按钮

  • Analyze requirement：触发需求分析。
  • Save business answers：保存业务反馈。
  • Ask follow-up questions：继续生成追问。
  • Approve solution：审批方案通过。
  • Return for revision：退回修改。
  • Start coding：进入 AI 编码。
  • Run tests：运行测试。
  • Request review：触发 CR。
  • Generate delivery report：生成交付报告。

8. 关键组件

组件 用途 状态要求
文件树 展示项目目录、文件类型、变更状态。 加载、空目录、搜索无结果、权限不足。
代码编辑器 查看和编辑代码。 只读、编辑、保存中、保存失败、冲突。
Diff 查看器 查看 AI 或人工修改。 新增、删除、修改、二进制变更、大文件。
问题列表 展示 AI 生成的需求澄清问题。 阻断、重要、普通、已回答、已关闭。
业务反馈表单 录入业务答案。 草稿、已保存、冲突、必填未填。
反思报告面板 展示阶段质量判断。 通过、阻断、需人工确认、证据缺失。
审批条 展示待审批人、审批动作和历史。 待审批、已通过、已驳回、已豁免。
运行日志 展示测试、构建、AI 任务日志。 运行中、成功、失败、超时、已取消。
CR 问题列表 展示代码审查问题。 阻断、建议、已修复、已豁免。
追溯链面板 展示需求到代码和测试的链路。 完整、缺失、证据失效、版本过期。

9. 状态与异常

空状态

  • 项目列表为空：提示创建第一个项目，说明支持 ZIP 和 Git 导入。
  • 需求为空：提示上传需求文档，并说明支持的格式。
  • 问题为空：说明 AI 没有发现阻断问题，允许进入方案阶段，但保留重新分析入口。
  • 测试为空：提示先配置测试命令或项目环境声明。

错误状态

错误 页面反馈 用户动作
项目上传失败 展示失败原因、支持格式、重试入口。 重新上传或联系管理员。
AI 输出不合法 提示结构化结果校验失败，展示重试按钮。 重试、人工接管或查看原始输出。
测试环境失败 区分环境失败和代码失败，展示环境配置入口。 修改环境声明或重试。
审批被驳回 展示驳回意见和退回阶段。 重新生成、编辑修改或补充说明。
证据链失效 提示需求或代码版本变化，要求重新生成上下文包。 重新生成分析或确认继续使用旧结果。

10. 响应式与可访问性

响应式策略

  • 桌面端是主体验，支持完整代码编辑、Diff、文档和审批。
  • 平板端保留项目查看、需求澄清、审批、报告查看，代码编辑可降级为只读。
  • 手机端只支持查看状态、填写简单业务反馈、审批和查看报告，不提供完整代码编辑。
  • 窄屏时右侧上下文面板变为抽屉，文件树可折叠。

可访问性要求

  • 所有按钮、输入框、菜单、标签页支持键盘访问。
  • 状态不能只靠颜色表达，必须同时有文字或图标标签。
  • 错误信息要靠近对应输入框，并说明如何修复。
  • 运行日志和长任务状态要能被屏幕阅读器感知。
  • 代码编辑区域要提供只读替代视图和复制能力。

11. 文案规范

场景 推荐文案 避免文案
触发需求分析 分析需求 开始智能探索
保存业务反馈 保存业务反馈 提交
审批方案 通过方案 OK
驳回 退回修改 不行
触发编码 开始编码 让 AI 干活
运行测试 运行测试 验证一下
生成报告 生成交付报告 完成
文案原则： 按钮要说明动作结果，错误要说明修复方式，AI 结论要避免绝对化表达。比如使用“建议进入方案阶段”，不要写“需求已经完全清楚”。

12. 页面验收标准

验收项 标准
流程可见 用户在任意项目页面都能看到当前阶段、下一步动作和阻断原因。
产物可查 每个阶段产物都有入口，能查看历史版本或当前版本。
AI 可控 AI 任务支持运行状态展示、失败原因、重试和人工接管。
代码可审查 所有代码变更都能在 Diff 中按文件查看。
审批明确 待审批事项显示审批人、审批动作、审批历史和驳回原因。
状态完整 主要页面具备加载、空状态、成功、失败、无权限状态。
窄屏可用 移动端至少能查看流程、填写业务反馈、完成审批和查看报告。
