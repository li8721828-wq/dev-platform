AI 代码开发平台 MVP 技术详细设计

本文档定义 MVP 版本的技术实现方案，覆盖服务拆分、核心状态机、接口设计、数据表设计、AI 编排、代码工作台、沙箱执行、权限审计和可观测性。 它承接总体设计、MVP 需求规格和产品原型说明，用于指导研发拆分和开发排期。

1. 技术范围

MVP 需要实现一条可运行的端到端链路，而不是完整企业级平台。本阶段技术设计优先保证稳定、可追溯、可人工接管。

MVP 技术假设

  • 前端使用 React 或 Vue 均可，代码编辑器建议使用 Monaco Editor。
  • 后端可采用 Java Spring Boot、Node.js NestJS 或 Go。本文档以服务边界和接口为主，不绑定具体语言。
  • 数据库使用 PostgreSQL，缓存和任务锁使用 Redis，对象文件使用本地文件存储或 MinIO。
  • AI 调用通过统一 AI Orchestrator 封装，业务服务不直接调用模型。
  • MVP 沙箱可先使用 Docker Runner，后续再升级 Kubernetes Job 或隔离更强的 Runner。
  • MVP 支持单 Agent 编码，多 Agent 先实现策略判断和任务拆分，不做复杂并行调度。
边界说明： 本文档可以写具体表、接口和状态机，因为它已经进入技术详细设计阶段；但字段类型和索引仍以 MVP 可实现为准，后续可在数据库设计评审中继续细化。

核心设计原则

  • 同步接口只负责创建任务和查询状态，AI、索引、测试、CR 均异步执行。
  • 所有阶段产物都保存版本，后续阶段引用固定版本，避免上下文漂移。
  • 代码变更始终发生在项目工作区或分支内，不直接修改原始上传包。
  • 所有 AI 产物必须经过结构化校验和反思门禁，失败时进入可恢复状态。
  • 所有关键动作写入审计日志，包括用户动作、AI 动作、系统动作和审批动作。

3. 服务模块

模块 职责 MVP 关键能力
web-console 前端工作台。 项目、代码、需求、澄清、方案、详细设计、编码、测试、CR 页面。
api-gateway 统一 API 入口。 鉴权、权限校验、请求聚合、SSE 事件订阅。
project-service 项目与成员管理。 项目创建、成员角色、项目状态、环境声明。
repo-service 代码仓库和文件工作区。 ZIP 解压、Git clone、文件树、文件读写、Diff、快照。
document-service 需求文档解析和版本管理。 文档上传、文本抽取、版本保存、片段引用。
workflow-service 阶段状态机和门禁。 阶段推进、审批、反思门禁、失败恢复、事件通知。
ai-orchestrator AI 调用统一编排。 上下文包、Prompt 版本、模型调用、JSON Schema 校验、重试。
agent-service Agent 任务管理。 需求分析 Agent、方案 Agent、详细设计 Agent、编码 Agent、测试 Agent、CR Agent。
sandbox-service 构建和测试运行。 Docker Runner、命令执行、日志采集、超时、资源限制。
review-service 代码审查和质量报告。 Diff 分析、CR 问题、严重级别、修复建议。

4. 工作流状态机

主状态

PROJECT_IMPORTED
  → REQUIREMENT_ANALYZING
  → REQUIREMENT_QUESTIONING
  → CLARIFYING
  → READY_FOR_SOLUTION
  → SOLUTION_GENERATING
  → SOLUTION_REVIEWING
  → DETAIL_DESIGN_GENERATING
  → DETAIL_DESIGN_REVIEWING
  → CODING
  → SELF_TESTING
  → CODE_REVIEWING
  → READY_TO_DELIVER
  → DONE

任意状态可进入：
  WAITING_HUMAN_APPROVAL
  PAUSED
  FAILED
  CANCELLED

状态流转规则

当前状态 事件 目标状态 校验
PROJECT_IMPORTED upload_requirement REQUIREMENT_ANALYZING 项目索引成功，需求文档解析成功。
REQUIREMENT_ANALYZING analysis_completed REQUIREMENT_QUESTIONING AI 输出问题清单通过 Schema 校验。
CLARIFYING clarification_ready READY_FOR_SOLUTION 无阻断级未知项，反思报告允许继续。
SOLUTION_REVIEWING approve_solution DETAIL_DESIGN_GENERATING 审批人角色为架构师或技术负责人。
DETAIL_DESIGN_REVIEWING approve_detail_design CODING 详细设计包含文件计划、任务计划和测试矩阵。
CODING coding_completed SELF_TESTING 存在代码 Diff，变更说明可解析。
SELF_TESTING tests_failed CODING 失败归因为代码问题，生成修复任务。
SELF_TESTING tests_passed CODE_REVIEWING 阻断级测试通过。
CODE_REVIEWING review_blocked CODING 存在高优先级问题且未豁免。
CODE_REVIEWING review_passed READY_TO_DELIVER 高优先级问题清零或有有效豁免。

6. API 设计

接口风格

  • REST API 负责资源管理和任务触发。
  • SSE 用于推送工作流、AI、测试、CR 的运行事件。
  • 所有长任务接口返回 run_id 或 task_id，前端通过事件接口订阅状态。
  • 所有写接口支持 Idempotency-Key 请求头，避免重复创建任务。

核心接口

接口 方法 说明 返回重点
/api/projects POST 创建项目。 project_id
/api/projects/{id}/upload POST 上传 ZIP 或绑定 Git 地址。 snapshot_id, index_task_id
/api/projects/{id}/tree GET 获取文件树。 files[]
/api/projects/{id}/files GET/PUT 读取或保存文件。 content, checksum
/api/projects/{id}/diff GET 查看工作区 Diff。 changed_files[]
/api/requirements POST 上传需求文档。 requirement_doc_id
/api/workflows POST 创建工作流。 workflow_id
/api/workflows/{id}/analyze-requirement POST 触发需求分析。 stage_run_id, agent_task_id
/api/clarifications/{id}/answers POST 提交业务反馈。 round_id, next_action
/api/workflows/{id}/generate-solution POST 生成方案设计。 artifact_id
/api/workflows/{id}/generate-detail-design POST 生成详细设计。 artifact_id
/api/workflows/{id}/start-coding POST 触发 AI 编码。 agent_task_id
/api/test-runs POST 运行测试命令。 test_run_id
/api/code-reviews POST 触发代码审查。 review_run_id
/api/approvals POST 提交审批结果。 approval_id, next_stage
/api/runs/{id}/events GET SSE 订阅运行事件。 event stream

7. AI 编排设计

调用流程

业务服务创建 Agent 任务
  → AI Orchestrator 生成上下文包
  → Prompt Registry 选择提示词版本
  → Model Router 选择模型
  → 调用模型
  → JSON Schema 校验
  → 失败时重试或进入人工接管
  → 保存结构化结果
  → 触发反思 Agent
  → 反思通过后通知 Workflow Service

Agent 输出 Schema

Agent 输出对象 必填字段
需求分析 Agent requirement_questions question, category, priority, why_needed, impact_scope, candidate_answers
澄清 Agent clarification_summary answer_summary, conflicts, unresolved_questions, can_continue
方案 Agent solution_design goal, scope, technical_approach, impacted_modules, risks, rollback_plan, agent_strategy
详细设计 Agent detail_design file_plan, api_design, data_design, flow_design, exception_design, test_matrix
编码 Agent code_change_plan changed_files, patch_refs, implementation_summary, risks, test_suggestions
测试 Agent test_analysis status, failed_commands, root_cause, fix_suggestions, environment_issue
CR Agent review_findings severity, category, file_path, line_no, issue, suggestion, blocking

上下文包策略

  • 需求分析阶段：需求文档片段、项目画像、关键目录结构、接口摘要。
  • 方案阶段：需求、澄清记录、项目画像、代码索引摘要、历史反思报告。
  • 详细设计阶段：方案设计、代码文件计划、接口和数据模型相关文件。
  • 编码阶段：详细设计、目标文件、相关引用文件、测试文件、禁止修改范围。
  • CR 阶段：最终 Diff、详细设计、测试报告、追溯链。

8. 代码工作台

工作区目录

workspace_root/
  projects/
    {project_id}/
      source/              原始代码或 Git 工作区
      snapshots/           阶段快照
      patches/             AI 和人工变更 Patch
      artifacts/           方案、设计、报告
      logs/                构建、测试、AI 执行日志

文件读写规则

  • 读取文件必须校验项目权限和路径合法性，禁止目录穿越。
  • 保存文件必须带上前端读取时的 checksum，避免覆盖其他修改。
  • AI 编码前创建工作区快照，失败时可以恢复到快照。
  • Diff 基于工作区当前状态和阶段基线生成。
  • 大文件、二进制文件、密钥文件默认只读。

代码索引

索引类型 MVP 实现 后续增强
文件索引 路径、大小、语言、checksum、文本摘要。 增量索引和文件热度。
全文索引 基于数据库或轻量搜索库。 专用搜索引擎。
符号索引 优先支持目标技术栈的函数、类、接口提取。 LSP / Tree-sitter 深度索引。
语义索引 MVP 可先做文件摘要级检索。 向量库和调用链融合检索。

9. 沙箱执行

任务生命周期

创建 test_run
  → 校验权限和环境声明
  → 准备工作区快照
  → 创建 Docker 容器
  → 注入允许的环境变量
  → 执行命令
  → 流式采集日志
  → 保存退出码、日志、耗时、资源使用
  → 销毁容器
  → 更新 test_run 状态

安全限制

限制项 MVP 要求
CPU / 内存 每个任务设置默认资源上限，管理员可配置。
执行时间 默认 30 分钟超时，超时后强制终止。
网络 默认禁止内网访问，允许配置依赖源白名单。
环境变量 只注入项目环境声明中允许的变量。
文件系统 容器只挂载当前工作区，不挂载宿主机敏感路径。

  • 代码修改、人工接管、测试执行、回滚。

11. 可观测性

日志

  • 业务日志：项目、工作流、阶段、审批。
  • AI 日志：模型、Prompt 版本、上下文包、耗时、失败原因。
  • 沙箱日志：命令、退出码、资源使用、运行日志 URI。
  • 安全日志：权限拒绝、敏感文件扫描、异常路径访问。

指标

指标 用途
workflow_stage_duration_seconds 观察阶段耗时。
agent_task_failure_total 观察 Agent 失败率。
ai_model_call_latency_seconds 观察模型调用耗时。
sandbox_run_failure_total 观察沙箱任务失败。
review_blocking_findings_total 观察阻断级 CR 问题。

12. MVP 部署

开发环境

  • Docker Compose 启动 PostgreSQL、Redis、MinIO 和后端服务。
  • 前端本地 dev server 连接后端 API。
  • 沙箱 Runner 可先使用本机 Docker。

测试环境

  • 后端服务容器化部署。
  • Runner 与业务服务分离部署，避免测试任务影响 API 服务。
  • 对象存储保存文档、Patch、日志和报告。

配置项

配置 说明
MODEL_PROVIDER 模型供应商。
MODEL_DEFAULT 默认模型。
WORKSPACE_ROOT 项目工作区根目录。
OBJECT_STORAGE_BUCKET 对象存储桶。
SANDBOX_IMAGE_DEFAULT 默认沙箱镜像。
SANDBOX_NETWORK_MODE 沙箱网络策略。
