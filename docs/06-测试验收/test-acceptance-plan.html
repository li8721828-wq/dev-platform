AI 代码开发平台测试与验收方案

本文档定义 AI 代码开发平台 MVP 的测试范围、测试类型、测试用例设计、AI 质量评估、Agent 调度测试、安全测试、性能测试和最终验收标准。 目标是确保平台不仅功能可用，而且 AI 输出可控、代码变更可审查、任务失败可恢复。

文档类型：测试与验收 版本：v0.1 适用范围：MVP 目录：docs/06-测试验收
1. 测试范围 2. 测试策略 3. 功能测试 4. 工作流测试 5. Agent 调度测试 6. AI 质量测试 7. 代码生成质量测试 8. 沙箱安全测试 9. 权限与审计测试 10. 性能与稳定性测试 11. 用户验收测试 12. 最终验收标准

1. 测试范围

范围 测试目标 MVP 是否必须
项目上传与代码工作台 验证项目导入、文件树、代码查看、编辑、Diff。 必须
需求澄清闭环 验证需求上传、AI 问题生成、业务反馈、多轮澄清。 必须
方案与详细设计 验证方案生成、详细设计生成、审批和反思门禁。 必须
AI 编码与自测 验证 AI 修改代码、生成 Diff、运行测试、失败修复。 必须
代码 CR 验证 AI 对 Diff 的审查能力和阻断问题闭环。 必须
Agent 串行和批量分发 验证不同 Agent 串行接力，以及同类型 Agent 分片并行和聚合。 必须覆盖基础场景
沙箱安全 验证测试执行不会影响宿主机、内网、密钥和其他项目。 必须

2. 测试策略

MVP 测试采用“功能正确性 + AI 输出质量 + 安全隔离 + 端到端验收”四层策略。

单元测试
  → 服务接口测试
  → 工作流状态机测试
  → Agent 输出 Schema 测试
  → 沙箱执行测试
  → 端到端流程测试
  → 用户验收测试

测试数据

  • 准备 3 个示例项目：小型后端项目、小型前端项目、含测试命令的全栈项目。
  • 准备 5 份需求文档：规则明确、规则缺失、存在矛盾、涉及接口变更、涉及数据变更。
  • 准备 3 类失败样本：AI 输出 Schema 错误、测试命令失败、沙箱环境失败。
  • 准备 2 类安全样本：包含疑似密钥文件、包含危险脚本命令。

3. 功能测试

编号 测试项 步骤 预期结果
FT-001 项目 ZIP 上传 创建项目，上传合法 ZIP。 上传成功，生成文件树和项目画像。
FT-002 文件树查看 进入代码工作台，展开目录并打开文件。 文件内容正确展示，路径和语言识别正确。
FT-003 代码编辑与保存 修改一个普通文本代码文件并保存。 保存成功，Diff 中展示变更。
FT-004 需求文档上传 上传需求文档并触发解析。 需求版本保存成功，解析文本可查看。
FT-005 业务反馈录入 对 AI 生成的问题填写业务答案。 答案保存成功，AI 可生成澄清摘要。
FT-006 审批驳回 方案阶段点击退回修改并填写原因。 工作流回到方案生成状态，保留驳回记录。
FT-007 最终交付报告 完成测试和 CR 后生成交付报告。 报告包含需求、澄清、设计、代码、测试、CR 链路。

4. 工作流测试

编号 场景 预期
WF-001 按正常路径从项目上传流转到交付报告。 每个阶段状态正确，阶段产物完整保存。
WF-002 需求澄清存在阻断问题。 不得进入方案阶段，页面展示阻断问题。
WF-003 方案审批被驳回。 回到方案生成阶段，驳回意见成为新上下文。
WF-004 测试失败且归因为代码问题。 回流到编码阶段，生成修复任务。
WF-005 CR 存在高优先级阻断问题。 不得进入最终交付，必须修复或审批豁免。
WF-006 AI 任务执行失败。 工作流进入 FAILED 或 WAITING_HUMAN_APPROVAL，不丢失上下文。

5. Agent 调度测试

串行 Agent 流水线

编号 场景 预期
AG-001 需求分析 Agent 完成后触发澄清 Agent。 澄清 Agent 输入包含问题清单和需求证据。
AG-002 澄清 Agent 判断可开发后触发方案 Agent。 方案 Agent 输入包含澄清摘要和决策记录。
AG-003 详细设计未审批时触发编码 Agent。 平台拒绝触发，提示详细设计未通过。

同类型 Agent 批量分发

编号 场景 预期
AG-101 按模块分发多个需求分析 Agent。 每个 Agent 只处理自己的模块上下文，聚合后问题去重。
AG-102 按文件分发多个 CR Agent。 聚合 Agent 合并问题，重复问题只保留一条。
AG-103 两个 Agent 对同一问题给出不同严重级别。 聚合 Agent 标记冲突，并采用更高严重级别或要求人工确认。
AG-104 一个子任务失败，其他子任务成功。 批量任务状态为部分失败，允许重试失败分片，不重复执行成功分片。
AG-105 批量分发任务超过并发上限。 调度器排队执行，页面展示等待状态和进度。

6. AI 质量测试

指标 测试方法 MVP 目标
问题有效率 业务确认 AI 生成问题是否有价值。 有效问题占比不低于 50%。
证据引用准确率 抽查 AI 引用的需求片段和代码文件是否真实支持结论。 不低于 80%。
Schema 通过率 统计 AI 输出一次通过结构化校验的比例。 不低于 90%。
反思命中率 注入已知缺陷，观察反思 Agent 是否识别。 阻断级缺陷必须识别。
澄清收敛能力 对同一需求进行多轮澄清，检查是否逐步减少未知项。 问题不应无限重复，必须能给出可开发性判断。

7. 代码生成质量测试

编号 测试项 预期
CQ-001 AI 按详细设计修改授权文件。 只修改授权范围内文件，Diff 可读。
CQ-002 AI 遇到信息不足。 停止并提出问题，不得扩大修改范围。
CQ-003 AI 修改后运行测试。 测试通过或能输出明确失败原因。
CQ-004 AI 修改与详细设计不一致。 CR Agent 或反思 Agent 能识别不一致。
CQ-005 人工接管后继续 AI 分析。 AI 使用人工修改后的最新快照，不使用旧上下文。

8. 沙箱安全测试

编号 场景 预期
SB-001 测试命令访问宿主机敏感路径。 访问失败，记录安全日志。
SB-002 测试命令访问内网地址。 默认阻断，除非在白名单中。
SB-003 测试命令超时。 容器被终止，test_run 标记为 timeout。
SB-004 项目包含疑似密钥。 上传后提示风险，密钥内容不得进入 AI 上下文。
SB-005 沙箱任务消耗过高资源。 触发资源限制，任务失败但平台服务正常。

9. 权限与审计测试

编号 测试项 预期
PA-001 只读用户尝试编辑代码。 操作被拒绝，并写入审计日志。
PA-002 业务确认人审批技术方案。 操作被拒绝，提示角色不匹配。
PA-003 技术负责人提交 CR 豁免。 豁免成功，必须包含原因和到期时间。
PA-004 查看审计日志。 能看到用户动作、AI 动作、审批动作和测试动作。

10. 性能与稳定性测试

测试项 目标
项目上传 中小型项目可以成功导入，长任务有进度反馈。
文件树加载 常规项目文件树可在可接受时间内展示，超大目录支持懒加载。
AI 任务并发 多个项目同时触发 AI 分析时，任务排队且互不影响。
沙箱并发 多个测试任务并发执行时，资源限制生效，API 服务不受影响。
失败恢复 服务重启后，运行中任务能恢复为可重试或失败状态，不丢失阶段产物。

11. 用户验收测试

验收角色

  • 项目负责人：确认端到端流程是否能跑通。
  • 业务确认人：确认 AI 问题是否有业务价值。
  • 架构师：确认方案和详细设计是否可评审。
  • 开发者：确认 AI 代码变更是否可读、可接管、可审查。
  • 测试负责人：确认测试报告和失败归因是否可用。

UAT 场景

  1. 导入一个真实项目。
  2. 上传一份存在业务规则缺口的需求文档。
  3. AI 生成澄清问题，业务确认人填写反馈。
  4. AI 判断可开发并生成方案设计。
  5. 架构师审批方案和详细设计。
  6. AI 修改代码并运行测试。
  7. CR Agent 审查代码，修复或豁免问题。
  8. 生成最终交付报告。

12. 最终验收标准

验收项 通过标准
端到端闭环 至少 3 个需求样例能完成从项目上传到交付报告的完整流程。
需求澄清质量 AI 生成问题中至少一半被业务确认有价值。
阶段门禁 阻断问题未关闭时，系统不得自动进入下一阶段。
Agent 调度 串行 Agent 接力正确，同类型 Agent 批量分发可完成分片和聚合。
代码可审查 AI 代码变更均可通过 Diff 查看，并关联详细设计任务。
测试可执行 构建、测试、Lint 至少一种命令可在沙箱中运行并产出日志。
安全隔离 沙箱不能访问宿主机敏感路径，密钥不能进入 AI 上下文。
审计可追溯 关键用户动作、AI 输出、审批、代码变更、测试和 CR 均有记录。
上线建议： MVP 通过验收后，先选择内部低风险项目试运行，观察 AI 问题有效率、代码一次通过率、CR 阻断问题数和阶段返工率，再逐步扩大使用范围。
